## 🚀 주요 프로젝트 · Selected Work

### [gongsiri: Financial Disclosure Risk Agent](https://github.com/GoBeromsu/gongsiri)

기업 공시를 해석하고 수집한 근거로 질의응답하는 agent의 AI risk-analysis layer를 구현했습니다.

**기여한 부분**

- 임시 텍스트 조합 로직을 Solar Pro 기반 risk-analysis engine으로 교체했습니다.
- 정량 공시 검사 뒤에 contextual LLM interpretation을 수행하는 2단계 분석 흐름을 설계했습니다.
- Evidence-grounded Q&A, 구조화된 위험 설명, JSON 복구와 deterministic fallback을 추가했습니다.
- 분석기를 프론트엔드와 cloud deployment 설정까지 포함한 서비스 형태로 확장했습니다.

Evidence: [Solar risk engine PR #14](https://github.com/GoBeromsu/gongsiri/pull/14) · [Authored PRs](https://github.com/GoBeromsu/gongsiri/pulls?q=is%3Apr+author%3Ahseo1o2)

### [PitchCoach: Document & Multimodal AI Coaching](https://github.com/Capstone-POKI/Pitchcoach-AI)

지원사업 공고문, IR deck, 발표 음성과 질의응답을 함께 분석하는 multimodal AI pipeline과 backend integration을 주도했습니다.

**기여한 부분**

- Document AI와 Gemini를 연결한 structured extraction pipeline을 안정화하고, 평가 기준과 점수에 evidence-aware fallback을 적용했습니다.
- 공고 요건과 IR deck 분석을 연결해 슬라이드 분류, OCR 정제, 기준별 점수와 설명, 보고서 생성을 구현했습니다.
- FastAPI 기반 비동기 deck 분석, Whisper 발표 분석, Gemini Q&A 평가 흐름을 만들었습니다.
- NestJS에서 AI job polling, 결과 저장, 버전 비교, 실패 상태, 인증과 EC2/Docker 배포를 연결했습니다.

Evidence: [Document pipeline #9](https://github.com/Capstone-POKI/Pitchcoach-AI/pull/9) · [IR analysis #19](https://github.com/Capstone-POKI/Pitchcoach-AI/pull/19) · [Voice analysis #21](https://github.com/Capstone-POKI/Pitchcoach-AI/pull/21) · [Backend AI sync #12](https://github.com/Capstone-POKI/Pitchcoach-BACK/pull/12)

### [IDly: AI Email Security Backend](https://github.com/IDlyProject/IDly-Back)

Gmail 수집과 AI 위험 분석, 보안 조치와 운영 안정화까지 backend의 주요 흐름을 담당했습니다.

**기여한 부분**

- 동의 상태를 반영한 Gmail onboarding, 분석 결과 저장, evidence 중복 제거와 Solar 보안 보고서를 구현했습니다.
- LLM이 공식 URL이나 위험도, 완료 상태를 임의로 바꾸지 못하도록 deterministic Action Assistant state machine을 설계했습니다.
- Refresh token rotation, 소유권 검사, rate limit, secret detection, log redaction과 LLM context masking을 적용했습니다.
- 대용량 메일 수집을 disk streaming 방식으로 바꾸고 retry, cooldown, memory cap과 schema validation을 추가했습니다.

Evidence: [Core backend flow #3](https://github.com/IDlyProject/IDly-Back/pull/3) · [Action Assistant #11](https://github.com/IDlyProject/IDly-Back/pull/11) · [Security hardening #18](https://github.com/IDlyProject/IDly-Back/pull/18) · [Streaming OOM fix #29](https://github.com/IDlyProject/IDly-Back/pull/29) · [Stability & AI mapping #45](https://github.com/IDlyProject/IDly-Back/pull/45)

### [Enterprise Due Diligence: Data-Grounded BI Agent](https://github.com/1eehvunzin/dive2026)

기업 실사와 후보 비교를 위해 data contract를 중심으로 BI backend를 구축했습니다.

**기여한 부분**

- 2,886개 기업의 재무, 고용, 특허, NTIS, 지원 이력과 산업 benchmark 데이터를 결합했습니다.
- Time leakage를 차단하고 결측값과 0을 분리했으며, 단위를 정규화하고 무작위 유사도를 cohort distance로 교체했습니다.
- Document Parse와 Solar Pro를 연결해 공고 요건을 원문, 페이지, review status와 함께 추출했습니다.
- Agent의 응답을 report field와 evidence ID로 제한하고, 생성 점수 오류와 과거 데이터 누수를 검사하는 regression test를 추가했습니다.

Evidence: [Backend & data contracts #1](https://github.com/1eehvunzin/dive2026/pull/1) · [Due-diligence report refinement #2](https://github.com/1eehvunzin/dive2026/pull/2)

### [upstage-research-cli: Research-to-Evaluation CLI](https://github.com/hseo1o2/upstage-research-cli)

AI 논문을 재사용 가능한 구현과 평가 workflow로 바꾸는 CLI와 Agent Skill을 혼자 개발했습니다.

**기여한 부분**

- Upstage Document Parse로 논문 구조를 보존하고 재현 가능한 방법론 요소를 찾습니다.
- 논문 근거에서 평가 코드와 정규화된 metric definition을 생성합니다.
- Regression fixture와 구조화된 출력을 포함한 Agent Skill 형태로 workflow를 패키징했습니다.

### [LOOPy: Location-Based Challenge & Stamp Backend](https://github.com/Organization-LOOPy/LOOPy-BE)

동네 카페 서비스의 challenge, stamp, notification과 deployment 흐름을 담당한 backend contributor입니다.

**기여한 부분**

- 챌린지 참여, 스탬프북, 이력, 사용 처리, 전화번호와 QR 적립, 점주와 관리자 기능을 구현했습니다.
- 큰 controller를 domain service와 공통 validation/date utility로 나누면서 frontend response contract를 유지했습니다.
- 카페 검색 filter와 notification authorization을 소유권과 사용자 opt-in 설정에 맞게 강화했습니다.
- Docker Compose 배포 흐름을 통합하고 port 충돌을 제거했으며, production 배포 실패가 CI에 반영되도록 수정했습니다.

Evidence: [Challenge domain #20](https://github.com/Organization-LOOPy/LOOPy-BE/pull/20) · [Stamp domain #66](https://github.com/Organization-LOOPy/LOOPy-BE/pull/66) · [Domain refactor #282](https://github.com/Organization-LOOPy/LOOPy-BE/pull/282) · [Deployment stability #299](https://github.com/Organization-LOOPy/LOOPy-BE/pull/299)
